# دسترسی خصوصی و ایجنت استقرار

## اطلاعات محرمانه
فایل مرجع محلی: `~/.config/promty/servers/production.env`، پوشه 0700 و فایل 0600. میزبان، پورت، نام کاربری و رمز/مسیر کلید در آن قرار می‌گیرند؛ داخل Git، Markdown، ZIP استقرار یا پیام گفتگو کپی نشوند. مالک اطلاعات را در فایل خصوصی ثبت کرده است؛ اطلاعات آن را وارد اسناد نکنید. اتصال SSH با alias `promty-production` و کلید سیستم، با کنترل کلید میزبان، به صورت خواندنی تأیید شده است. برای اتصال از `~/.ssh/config` و احراز هویت امن سیستم استفاده کنید؛ فایل قدیمی رمز مسیر خودکار ورود نیست.
کلید SSH + ssh-agent ترجیح دارد. اگر password استفاده می‌شود، از prompt تعاملی SSH یا اتصال امن پیکربندی‌شده استفاده کنید؛ پسورد را در argv، sshpass -p، history یا خروجی tool قرار ندهید. فایل permission محدود، vault رمزگذاری‌شده نیست؛ سیستم باید امن باشد.
SSH StrictHostKeyChecking فعال باشد. اثرانگشت میزبان نخست از مسیر مستقل مالک تأیید شود؛ از StrictHostKeyChecking=no استفاده نشود. agent تنها در محیطی که دسترسی فایل و شبکه مجاز است می‌تواند متصل شود.

## پرامپت آماده برای چت جداگانه
> نقش تو Deployment & Recovery است. مخزن فعال /home/sajj/Documents/Codex/promty/ui-preview و برنچ release را بررسی کن. ابتدا AGENTS.md، docs/project-context.md، docs/deployment-agent.md، docs/postgresql.md و SERVER_UPDATE.md را بخوان. از Skill نصب‌شده promty-deploy و alias تأییدشده promty-production در SSH config استفاده کن؛ رمز، کلید و token را از فایل قدیمی به argv/log/اسناد منتقل نکن. ابتدا فقط بررسی خواندنی انجام بده: هویت و اثرانگشت میزبان، مسیر پروژه و cwd سرویس، نسخه Node، PM2، پورت‌ها، Nginx Proxy Manager، نوع ذخیره‌ساز واقعی محیط PM2 و فایل، نسخه Git/Build و فضای دیسک. به سایر سایت‌ها و سرویس‌ها دست نزن. اگر دسترسی نیست دقیق گزارش بده. برای هر انتشار طرح مشخص شامل SHA نسخه، diff، فایل‌های انتقالی، بکاپ پایگاه/رسانه/تنظیمات، مهاجرت غیرمخرب، زمان نگهداری، تست پذیرش و بازگشت تهیه کن. پیش از آپلود فایل، تغییر پایگاه، تغییر سرویس یا ری‌استارت از مالک تأیید همان طرح را بگیر؛ تأیید قبلی را فقط در محدوده همان طرح معتبر بدان. اجرای دستور فقط‌خواندنی مجوز تغییر نیست. به‌روزرسانی نسخه فقط از کامیت ثبت‌شده باشد؛ main را merge/push و history را rewrite نکن. دیتابیس مقصد PostgreSQL باید صریح مشخص شود؛ از JSON به‌عنوان fallback پنهان استفاده نکن. داده واقعی را با نمونه جایگزین نکن؛ مالک پایگاه تازه را بدون انتقال محتوای تاریخی انتخاب کرده است، اما عملیات سرور فقط پس از تأیید طرح docs/postgresql-production-plan.md مجاز است؛ از db push/reset/seed عمومی و rsync --delete استفاده نکن. با حفظ db.json، .env، dl و .private اجرا کن. پس از اجرای مجاز، سلامت API و مرورگر، نقش مدیر، خصوصی‌بودن draft، رسانه، جستجو و چرخه انتشار را آزمون و گزارش کن. SSH موفق به معنی deploy موفق نیست. رمزها و متن محتوای خصوصی سرور در گزارش نیایند.

این متن راهنمای چت است، نه Agent نصب‌شده. فایل اجرایی سفارشی Codex باید TOML معتبر در .codex/agents باشد و فعال‌شدن آن در محیط واقعی جدا آزموده شود. در این مرحله config اجرایی یا چت مستقل ایجاد نشده است.
