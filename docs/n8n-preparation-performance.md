# سرعت آماده‌سازی پرامپت خام

تاریخ: ۲۰۲۶-۱۰-۲۴. هدف تأییدشده مالک: دریافت خروجی کامل قابل ورود به فرم، از n8n در حداکثر ۳۰ ثانیه؛ timeout یا پاسخ اولیه موفقیت محسوب نمی‌شود.

## شواهد فعلی

اجرای ارسالی مالک: ۲ دقیقه و ۱۷٫۳۵۴ ثانیه، ۱۴۶٬۴۱۲ توکن. اصلاح قبلی طبق یادداشت همین گفتگو: حدود ۲ دقیقه و ۲۴ ثانیه، ۸۴٬۰۹۱ توکن و ۵ فراخوانی مدل؛ نتیجهٔ نهایی از داشبورد تأیید نشده بود. این اعداد benchmark نامزد جدید نیستند.

نسخهٔ ذخیره‌شدهٔ ۲۲ اکتبر شامل Router مدل، شاخه تخصصی، QA مدل با حداکثر ۸ iteration، خواندن اولیه واژگان/قواعد/پیشنهادها و بازخوانی هر سه پس از QA است. Design و QA به‌تنهایی مجموع ۳۲٬۳۷۴ نویسه System دارند و بدنه/ترجمه و metadata به مدل دوم دوباره داده می‌شوند. تغییر streaming برای عبور از idle timeout، به‌خودی‌خود زمان آماده‌سازی را کم نمی‌کند.

## نامزد اولیه و حدودش

[راهنمای دقیق و فایل‌ها](../n8n-agaent/fast-preparation/v001/README.md): یک درخواست مدل؛ همهٔ کاربردهای فعال در فهرست فشرده؛ دو خواندن شیت، بدون tool loop، بازنویسی QA یا صف‌نویسی همزمان؛ کنترل JSON، کاتالوگ، فیلد و برابری متغیرها با کد. مدل موجود حفظ شده و reasoning درخواست خاموش است. System برابر ۵٬۰۴۰ نویسه است؛ این عدد تعداد توکن نیست.

برای کاهش زمان، فقط صرفه‌جویی متنی و حذف مراحل تکراری انجام شده است. حفظ تمام قیود منبع و دو زبان شرط است. مدل دوم QA اجرا نمی‌شود، پس خروجی پیش‌نویس و needsReview=true دارد؛ صحت معنایی و کیفیت فارسی/انگلیسی باید بازبینی شوند. هیچ پیشنهاد تازه‌ای خودکار active یا ذخیره‌شده معرفی نمی‌شود.

## وضعیت قبلی (قبل از اتصال دوبارهٔ Chrome)

نامزد بر اساس snapshot قدیمی آماده شد، نه export تازهٔ live. در n8n اعمال یا منتشر نشده است. ۹ بررسی محلی با خروجی واقعی قبلی مالک و fixture شیت پاس شدند؛ آزمون مدل یا latency جدید نیستند. مسیر لوکال normalizeAgentAnalysis، ورود کاربرد/نوع منبع و metadata PostgreSQL از کار قبلی محفوظ‌اند؛ هنوز همان بخش ناتمام end-to-end هستند.

ابزار مرورگر پیام Local browser use is disabled in Work settings می‌دهد. دسترسی به workflow زنده و اجرای واقعی تا فعال‌شدن ابزار متوقف است؛ SSH/پایگاه n8n یا استخراج credential برای دورزدن این محدودیت انجام نشد. هیچ تغییری روی سرور برنامه انجام نشده است.

## کار باقی‌مانده برای پذیرش

۱. خواندن export و executionهای جدید مالک از workflow زنده، حفظ تغییرات جدید و بکاپ قبل از اعمال.
۲. اعمال نامزد در draft تست، بررسی resolve شدن credentialهای قبلی و model parameters توسط provider.
۳. اجرای واقعی چند بار با پرامپت کارتونی و نمونه‌های متنی/کدنویسی، ثبت زمان کل، مرحله شیت و مدل، تعداد call و توکن. پاسخ بریده/timeout/JSON خراب رد شود؛ benchmark.py فقط یک نمونهٔ real را می‌سنجد و اثبات p95 نیست.
۴. بازبینی معنا، قیود عکس مرجع، متن فارسی/انگلیسی و جایگذاری فیلدها، سپس تست کامل dashboard→API→n8n→form در لوکال.
۵. برای کار رسمی ادمین‌ها، endpoint تولیدی پایدار و امن و همزمانی بررسی شود. تغییر فعلی production را عمداً رد می‌کند؛ Publish خودکار یا تغییر وبهوک سایت انجام نشده است. انتشار کد سایت و migration metadata، در صورت نیاز، مرحلهٔ مستقل با Commit و طرح مشخص است.

موفقیت فقط پس از دریافت خروجی کامل و معتبر در کمتر از ۳۰ ثانیه گزارش می‌شود. محدودکردن timeout یا نمایش زودتر spinner، راه‌حل این معیار نیست.

## بررسی تازهٔ Chrome در ۲۴ اکتبر

مرورگر دوباره وصل شد و export واقعی workflow اصلی بکاپ شد. مدل فعلی `models/gemini-3.8-flash` است؛ نامزد قبلی DeepSeek مبنای اعمال زنده قرار نگرفت. [نسخهٔ Gemini](../n8n-agaent/fast-preparation/v002/README.md) با همان Credential reference ساخته شد؛ `thinkingLevel=LOW` و یک درخواست با بودجهٔ ۶۰۰۰ توکن خروجی. این مدل در حالت LOW است، نه reasoning خاموش.

نسخه روی بوم آزمایشی جدا با نام «Promty — سریع Gemini — تست ۳۰ ثانیه» و شناسهٔ `gaaunEOXwrtDtqqS` از طریق clipboard خود n8n وارد شد. نسخهٔ اصلی و فعال `93Uq9lGFxbSJMGoY` تغییر نکرد. Publish انجام نشد. وارد شدن روی بوم، به‌تنهایی read-back/hash یا پذیرش عملکرد نیست.

اولین اجرای واقعی در UI با `Success in 28.579s` پایان یافت، اما بدنهٔ نتیجه `ok=false / MODEL_REQUEST_FAILED / httpStatus=502 / durationMs=26657` بود؛ HTTP node در ۲۳٫۷۸ ثانیه با `timeout of 23700ms exceeded` تمام شد. این اجرا خروجی محتوا نداشت و معیار ۳۰ ثانیه را پاس نکرد. تست مجدد اتصال Credential در UI موفق شد. رابط n8n متناوباً Offline شد؛ این موضوع جدا از زمان تولید متن بررسی می‌شود.

۹ آزمون محلی نسخهٔ Gemini پاس شدند. هنوز benchmark موفق، آزمون معنایی و اتصال کامل از داشبورد اثبات نشده‌اند. آزمایش کوتاه به پاسخ تأییدشده نرسید؛ اجرای بعدی با Problem running workflow و Offline متناوب مواجه شد. متن کامل درخواست در UI بازگردانده شد، اما read-back ذخیرهٔ نهایی پس از قطع ارتباط تأیید نشده است. تب آزمایشی برای ادامه محفوظ است؛ انتشار اصلی و تنظیمات سایت تغییر نکردند.

## نتیجهٔ تست واقعی پس از بازیابی مرورگر

دسترسی داخلی برقرار شد. عبارت خراب ذخیره‌شدهٔ jsonBody به `={{ JSON.stringify($json.request) }}` اصلاح و خطای syntax برطرف شد. Gemini 3.8 در دو تست 503/timeout داد. روی draft آزمایشی، Flash-Lite با JSON Schema بومی آزمایش شد؛ آخرین System v004 است. متن کامل Code نود ساخت درخواست از UI با نامزد تطبیق داده شد.

دو اجرای نهایی **۱۵٫۰۴۵** و **۲۲٫۳۴۳ ثانیه** طول کشیدند و از کنترل ساختاری گذشتند؛ گزینهٔ پیش‌فرض هر دو متن کامل انگلیسی منبع را بازسازی می‌کند. بازبینی فارسی و شرط عکس مرجع انجام شد. بااین‌حال گزینهٔ رنگ جایگزین در اجرای دوم با پالت ثابت متناقض است، و پذیرش همهٔ گزینه‌ها، end-to-end داشبورد، p95 و آمادگی انتشار هنوز تأیید نشده‌اند.
