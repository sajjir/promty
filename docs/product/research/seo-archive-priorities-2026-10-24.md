# سه اولویت شروع پرامتی با محور SEO و ارزش محتوا

تاریخ: ۲۰۲۶-۱۰-۲۴. وضعیت: پیشنهاد در پاسخ به درخواست تازه مالک؛ مجوز پیاده‌سازی یا انتشار نیست. این گزارش، اولویت‌های سئویی گزارش بازار قبلی را برای شروع مبتنی بر جستجو بازتنظیم می‌کند. فایل‌های کد و تغییرات ناتمام قبلی دست‌نخورده‌اند.

## تشخیص

آرشیو «گروه ← کاربرد» پایه مناسبی برای پیدا کردن محتواست. ارزش سئویی آن زمانی بالفعل می‌شود که کاربردهای منتخب، صفحه قابل کشف با راهنمای انتخاب و محتوای متمایز داشته باشند. زیاد شدن دسته‌ها، برچسب‌ها یا ترکیب فیلترها به خودی خود مزیت نیست. پیشنهاد مخاطب آغازین همچنان صاحبان فروشگاه‌های کوچک و ادمین‌های محتوای آن‌هاست؛ سه محور محتوایی مرتبط انتخاب شوند تا هرکدام کار مشخصی را برای همین مخاطب انجام دهند.

## شواهد تازه

- کد بررسی‌شده: checkout فعال `ui-preview` روی `finaly`، شامل تغییرات موجود کاربر. این کد معادل قطعی artifact سرور فرض نشده است.
- `src/lib/archiveCatalog.ts`: گروه/کاربرد محور اصلی؛ ابزار، نوع منبع، خروجی و زبان فیلترهای مکمل. «معرفی محصول» زیر کسب‌وکار قرار دارد.
- `src/components/ArchiveDiscovery.tsx`: انتخاب گروه‌ها با button و تغییر query انجام می‌شود؛ مسیر مستقل گروه/کاربرد در `src/App.tsx` وجود ندارد. لینک برخی آرشیوها از قفسه‌ها و صفحه جزئیات وجود دارد؛ ادعای «هیچ لینک داخلی وجود ندارد» صحیح نیست.
- `src/pages/Homepage.tsx`: ادامه نتایج با دکمه load more و درخواست API دریافت می‌شود. لینک مستقیم صفحه‌های بعدی آرشیو باید اضافه شود تا کشف محتوا به کلیک وابسته نماند.
- `server.ts`: عنوان و توضیحات پویا برای detail/tool/domain وجود دارد. تولید metadata از `req.path`، کاربردهای query را پوشش نمی‌دهد؛ فقط title قبلی حذف می‌شود و description پایه نیز باقی می‌ماند.
- `src/components/AuthContext.tsx`: تنظیم برند می‌تواند document.title را بازنویسی کند؛ حفظ عنوان اختصاصی بعد از رندر باید در پذیرش مرورگر بررسی شود.
- HTTP عمومی سایت: `/`، `/?group=social` و یک detail فعال همگی ۲۰۰؛ HTML اولیه فاقد محتوای اصلی و لینک کارت‌ها و دارای root خالی بود. این مشاهده، اثبات «ایندکس نشدن در گوگل» نیست؛ رندر واقعی Googlebot بررسی نشده است.
- همان صفحات دو meta description و هیچ canonical در HTML اولیه داشتند. detail عنوان اختصاصی داشت؛ query گروه همان عنوان عمومی خانه را داشت.
- دو مسیر `/prompts/:id` و `/prompt/:id` برای یک نمونه فعال، بدون redirect پاسخ ۲۰۰ داشتند؛ مسیر مفرد عنوان عمومی داشت. یک URL اصلی انتخاب و دیگری به آن هدایت شود.
- `/robots.txt` و `/sitemap.xml` در بررسی زنده ۲۰۰ با `text/html` و پوسته برنامه برگرداندند؛ فایل معتبر robots/XML نیستند.
- یک detail ساختگی در Production واقعاً ۴۰۴ داد؛ «همه صفحات ناموجود ۲۰۰ می‌دهند» یافته این بررسی نیست.
- API عمومی در زمان بررسی شش prompt فعال داشت: چهار `reference-portrait` و دو `social-profile`، شامل سه عنوان نزدیک کارتونی. این عکس لحظه‌ای است؛ سه عنوان مشابه به‌تنهایی اثبات یکسان بودن محتوا یا لزوم حذف نیست. خروجی و هدف آن‌ها باید قبل از ادغام مقایسه شود.

## اولویت ۱ — تکمیل قابلیت کشف و خواندن صفحات

کار توسعه: HTML محتوای عمومی صفحات منتخب و لینک‌های آن‌ها در پاسخ اولیه قابل خواندن باشد؛ فرم شخصی‌سازی می‌تواند تعاملی باقی بماند. رندر سمت سرور یا پیش‌رندر با تازه‌سازی پس از انتشار/ویرایش/لغو انتشار راهکار قابل بررسی است؛ بازنویسی کامل برنامه از این پیشنهاد نتیجه نمی‌شود. Google قادر به رندر JavaScript است، اما وابستگی کمتر به رندر برای این آرشیو توصیه می‌شود.

یک title، description و canonical سازگار با محتوای واقعی برای هر صفحه؛ حفظ عنوان بعد از اجرای برنامه؛ یک URL اصلی برای هر منبع و redirect دائمی alias؛ فایل robots معتبر و sitemap شامل URLهای اصلی، عمومی و منتشرشده. خطای واقعی ۴۰۴، عدم افشای draft و کنترل موبایل در پذیرش حفظ شوند. بهبود schema جای محتوای قابل خواندن را نمی‌گیرد.

پذیرش: صفحه جزئیات و هر آرشیو منتخب مستقیماً باز شوند، محتوای عمومی و لینک‌های مهم در HTML وجود داشته باشند، URL تکراری مستقل عرضه نشود و فایل‌های robots/sitemap نوع و محتوای صحیح داشته باشند. پس از انتشار مجاز، رندر و قابلیت ایندکس چند URL نمونه با URL Inspection و sitemap در Search Console بررسی شود؛ صرف valid بودن sitemap تضمین ایندکس یا رتبه نیست.

## اولویت ۲ — تبدیل آرشیو کاربردی به صفحات منتخب سئو

سه مجموعه آغازین: «محتوای اینستاگرام فروشگاهی»، «تصویر محصول» و «توضیحات محصول». این‌ها نماهای تحریری از منابع موجودند؛ لازم نیست تمام طبقه‌بندی یا شناسه‌های داده عوض شوند. برای هر مجموعه یک صفحه عمومی با URL پایدار، عنوان روشن، راهنمای انتخاب بین نمونه‌ها و لینک مستقیم به محتوا ساخته شود.

| نوع صفحه | سیاست پیشنهادی |
| --- | --- |
| جزئیات منبع کامل، منتشرشده و متمایز | قابل ایندکس، canonical به خودش، در sitemap |
| مجموعه منتخب با راهنمای مفید و منابع مرتبط | قابل ایندکس، canonical به خودش، لینک از خانه و منابع |
| نتایج جستجوی داخلی و ترکیب‌های دلخواه فیلتر | هدف سئو نباشند؛ برای وضعیت فعلی noindex و خارج از sitemap، با امکان خواندن noindex توسط خزنده |
| فقط تغییر مرتب‌سازی یا URL معادل | تجمیع URLهای واقعاً معادل؛ canonical به نسخه اصلی مناسب؛ از canonical کردن مجموعه‌های متفاوت به خانه پرهیز شود |
| صفحه‌بندی واقعی مجموعه | URL و لینک قابل خزش، canonical خود صفحه؛ نه canonical همه صفحه‌ها به صفحه اول |
| دسته خالی، برچسب کم‌محتوا یا محتوای ناقص | تا زمانی که ارزش مستقل ندارند وارد صفحات هدف و sitemap نشوند؛ مسیرهای نامعتبر پاسخ مناسب داشته باشند |

در مقیاس بزرگ‌تر می‌توان سیاست کنترل خزش فیلترها را سخت‌تر کرد؛ robots blocking و noindex هم‌زمان برای یک URL به‌عنوان راه حذف از ایندکس استفاده نشوند، چون خزنده noindex را نمی‌بیند. canonical نیز جایگزین عمومی مدیریت خزش نیست.

درخت پیشنهادی نمونه: خانه ← سوشال مدیا ← مجموعه اینستاگرام فروشگاهی ← پرامپت کپشن معرفی محصول. هر منبع یک کاربرد اصلی و یک URL اصلی داشته باشد و از مجموعه‌های مرتبط به همان URL لینک داده شود. نمایش یک منبع در چند مجموعه نیاز به ساخت نسخه تکراری آن ندارد. ساخت تصویر محصول طبق ساختار موجود زیر «کسب‌وکار ← معرفی محصول» بماند؛ از طراحی بصری هم می‌توان به همان صفحه لینک داد.

ابزارهایی مثل ChatGPT/Gemini و نوع منبع Prompt/Skill/Agent Guide ابتدا فیلتر مکمل‌اند. صفحه مستقل برای هر ابزار یا نوع منبع فقط با ارزش و محتوای متمایز توجیه دارد؛ ضرب کردن هر پرامپت در ابزارها، صنایع و مترادف‌ها راه تولید صفحات هدف نیست. نام فارسی یا انگلیسی slug به‌تنهایی امتیاز قطعی ایجاد نمی‌کند؛ URLهای فعلی را صرفاً برای زیباتر شدن مهاجرت ندهید.

پذیرش: سه مجموعه مفید، مسیر لینک‌دار خانه تا منبع، دسترسی لینک‌دار به ادامه فهرست، یک URL اصلی برای هر منبع و سیاست روشن ایندکس فیلترها. تعداد ثابتی از کلمات یا آیتم‌ها شرط گوگل نیست؛ مجموعه‌ای با یک منبع و بدون کمک مستقل به انتخاب، فعلاً نیاز به صفحه سئویی جدا ندارد.

## اولویت ۳ — صرف وقت ادمین‌ها برای نتیجه قابل اثبات

تقسیم زیر پیشنهاد تخصیص زمان تحریری دو هفته نخست است، نه سهم بازار یا حجم جستجو:

| سهم زمان | محور | جایگاه در آرشیو موجود | محتوای اول |
| --- | --- | --- | --- |
| ۵۰٪ | محتوای اینستاگرام فروشگاهی | social؛ کپشن `soc-04`، تقویم `content-calendar`، ریلز `soc-07`، سپس استوری/کاروسل | کپشن معرفی محصول، سناریوی ریلز قابل ضبط، تقویم هفتگی |
| ۳۰٪ | تصویر محصول | business → product → `product-image` | عکس زمینه سفید و صحنه استفاده واقعی؛ ورودی و خروجی کنار هم |
| ۲۰٪ | توضیحات محصول فروشگاه اینترنتی | business → product → `bus-15` | توضیح محصول بر اساس مشخصات واقعی؛ سپس راهنمای انتخاب و پاسخ به سؤال خرید |

دلیل رتبه اول: کار تکرارشونده همان مخاطب، امکان آزمایش متنی و پیوند طبیعی چند نیاز. دلیل رتبه دوم: نتیجه قابل نمایش و ارزش روشن برای فروشگاه، با هزینه و دشواری کنترل تصویر. دلیل رتبه سوم: نیاز مشخص نزدیک به خرید و تکمیل همان مسیر محصول. این اولویت‌بندی قضاوت محصول/تحریری است؛ داده Keyword Planner، Search Console یا نرخ تبدیل برای اثبات حجم تقاضا در اختیار این بررسی نیست. جستجوی عمومی فقط برای شناخت نوع صفحات و عبارت‌ها استفاده شده است.

حداقل هر صفحه: هدف مشخص و عنوان طبیعی؛ متن قابل شخصی‌سازی؛ ورودی نمونه کامل؛ خروجی واقعی همان اجرا؛ ابزار/مدل و تاریخ آزمون؛ راهنمای کوتاه استفاده و محدودیت؛ نام نویسنده یا بازبین مسئول؛ لینک به مجموعه و گام مرتبط. مثال نمایشی باید از نتیجه آزمون‌شده تفکیک شود. فرم و کپی آسان، خود بخشی از ارزش صفحه است؛ مقاله طولانی یا تعداد کلمه اجباری پیشنهاد نمی‌شود.

برای تصویر، حفظ ویژگی واقعی محصول، نوشته/لوگو و تطابق رنگ بررسی و محدودیت آشکار شود؛ خروجی زیبا به‌تنهایی کافی نیست. تصویر شاهد با اندازه مناسب و alt توصیفی، به‌جای تصویر تزئینی یا انباشت کلمات کلیدی استفاده شود. برای متن، اطلاعات محصول و ادعاها نباید ساخته شوند. نسخه‌های صرفاً تغییرنام‌یافته برای صنایع مختلف به جای صفحات جدا در مثال‌ها یا تنظیمات همان منبع قرار بگیرند، مگر اینکه مسئله و پاسخ واقعاً متفاوت باشد.

شروع تحریری: شش صفحه کامل، شامل سه مورد اجتماعی بالا، دو تصویر محصول و یک توضیح محصول. انتشار مجموعه‌ها تابع کیفیت و ارزش مستقل آن‌ها باشد؛ این شش عدد سهمیه گوگل یا شرط کافی رتبه گرفتن نیست. ادامه وقت ادمین‌ها صرف تکمیل و اصلاح همین مجموعه‌ها شود. انباشت پرتره‌های ترند مشابه، باز کردن همه حوزه‌ها و توسعه انبوه Skill/Agent Guide فعلاً اولویت پایین‌تری دارند.

پذیرش ارزش: فردی از مخاطب هدف با ورودی تازه، پرامپت را شخصی‌سازی و اجرا کند و نتیجه را با اصلاح کم قابل استفاده بداند؛ ایرادها ثبت و محتوا اصلاح شوند. سنجش بعد از انتشار: ایندکس و نمایش/کلیک هر مجموعه در Search Console، سپس شخصی‌سازی/کپی و بازخورد درباره خروجی واقعی. شمارنده کپی به‌تنهایی سنجه نتیجه نیست. سهم زمان‌ها پس از داده کافی بازنگری شود، نه براساس چند روز بی‌کلیکی.

## منابع اولیه

- [مبانی SEO جاوااسکریپت](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics): رندر، متادیتا و canonical؛ وجود JS برابر با عدم ایندکس نیست.
- [مدیریت خزش فیلترها](https://developers.google.com/crawling/docs/faceted-navigation): هزینه URLهای ترکیبی و تفکیک صفحات لازم از فیلترهای غیرضروری.
- [لینک‌های قابل خزش](https://developers.google.com/search/docs/crawling-indexing/links-crawlable): لینک واقعی با href.
- [صفحه‌بندی و بارگذاری تدریجی](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading): امکان دسترسی خزنده به ادامه محتوا.
- [قاعده noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing): ضرورت باز بودن خزش برای مشاهده قاعده.
- [محتوای مفید برای انسان](https://developers.google.com/search/docs/fundamentals/creating-helpful-content): تمرکز مخاطب، تجربه مستقیم، ارزش اصیل و نبود تعداد کلمه ترجیحی.

این مرحله فقط بررسی عمومی HTTP، مطالعه کد و منابع رسمی و ثبت پیشنهاد بود؛ اجرای مدل، تغییر محتوا/کد، آزمون محصول جدید و انتشار انجام نشد.
