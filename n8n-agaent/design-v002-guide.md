# راهنمای نسخهٔ دوم Design و QA/Verifier

وضعیت جدیدتر: پس از دریافت export دوم و مشاهدهٔ fieldsSchema خالی، [بررسی و نسخه‌های جایگزین جدید](reviews/empty-fields-2026-10-17/review.md) ثبت شدند. آخرین Design نسخهٔ v005 و QA نسخهٔ v004 است؛ هر دو یک پیام کامل Prompt دارند. راهنمای زیر مربوط به نسخهٔ دوم و سابقهٔ تصمیم‌های آن است.

به‌روزرسانی: به درخواست مالک، Design در نسخهٔ v003 به یک پیام کامل در Prompt / User Message تبدیل شد؛ [متن آمادهٔ کپی](02-design/prompt-only.md). برای این حالت، Prompt روی Expression باشد و System Message سفارشی خالی بماند. دستور جداسازی System/User در ادامه مربوط به v002 است؛ تنظیم QA فعلاً همان نسخهٔ دوم است.

تاریخ: ۲۰۲۶-۱۰-۱۷. وضعیت: پیشنهادی، آمادهٔ کپی و آزمون؛ هنوز روی n8n اعمال نشده است. محدودهٔ بازنویسی: فقط Design و QA/Verifier. متن سایر ایجنت‌ها در این مرحله بازنویسی نشده است.

## متن کامل آمادهٔ کپی

- [Design — متن جاری کامل](02-design/current.md)
- [QA/Verifier — متن جاری کامل](05-qa-verifier/current.md)

هر فایل دو بخش دارد: System Message و User Message / Expression. در نود مربوط، Prompt را روی Define Below بگذارید؛ متن System را در Options → System Message با حالت Fixed وارد کنید و مقدار User را در Prompt با حالت Expression قرار دهید. متن قبلیِ ترکیبی Prompt باید با User جدید جایگزین شود تا دستورهای قدیمی و جدید هم‌زمان وارد مدل نشوند. وجود این دو تنظیم در [مستند رسمی Tools Agent](https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.agent/tools-agent/) توضیح داده شده است؛ عنوان کنترل ممکن است با نسخهٔ رابط کمی فرق کند.

در آرشیو User با `={{ ... }}` نوشته شده که مقدار مناسب export است. در ویرایشگر Expression خود n8n، عبارت را از `{{` تا `}}` وارد کنید؛ `=` نشانهٔ ذخیره‌سازی export است و نباید به‌صورت متن اضافی وارد پیام مدل شود. preview باید یک JSON شامل sourceText/allowedTaxonomies و در QA همچنین candidate نشان دهد. تمام داده در یک JSON.stringify قرار دارد تا متن خامِ دارای آکولاد دوباره به expression تبدیل نشود.

اصل نسخهٔ اول نگهداری شده و نسخهٔ دوم علاوه بر current.md در `v002-proposed.md` هر پوشه ثبت است. current.md آخرین متن آماده‌شده است، نه ادعای فعال بودن آن در n8n.

## اثر بر نمونهٔ عکس به کارتون

در خروجی ارسالی، art_style و color_palette و sky_color مستقل نیستند: گزینهٔ انیمه با هویت سبک اصلی، گزینهٔ تک‌رنگ با متن پاستلی و رنگ‌های ثابت، و رنگ‌های نمایشی آسمان با هدف حفظ صحنه ممکن است تعارض داشته باشند. همچنین language به اشتباه persian است در حالی که body انگلیسی است؛ industry در محصول مصرف نمی‌شود و Pro tip مفید حذف شده است.

این نمونه پاسخ نهایی پس از QA و Code است؛ خروجی مستقل Design ارائه نشده، بنابراین نسبت دادن تک‌تک تغییرات به خود Design قطعی نیست. بازنویسی هر دو ایجنت این زنجیره را پوشش می‌دهد.

نسخهٔ جدید محافظه‌کارانه دو کنترل سازگار پیشنهاد می‌کند: ضخامت خطوط و شدت ملایم سایه‌زنی. سبک دستی دوبعدی، پالت پاستلی، هویت و ترکیب‌بندی، رنگ لباس، نسبت عکس، ممنوعیت تغییر اشیای مهم و دستور استفاده از یک عکس در هر بار حفظ می‌شوند. اگر در نمونهٔ دیگری هیچ انتخاب مفیدی وجود نداشت، fieldsSchema خالی مجاز است؛ دو فیلد قانون همگانی نیست.

[ورودی نمونه](examples/photo-to-cartoon/source.md) از پیام مالک با شکست خط عادی ثبت شده است. [خروجی مرجع پیشنهادی](examples/photo-to-cartoon/reference-output.json) دستی تألیف شده، خروجی اجرای Gemini نیست. تفاوت‌های هدفمند دیگر در آن: «ظاهر بامزه بدون تغییر تناسب بدن» برای رفع تعارض خود منبع، و «اشیاء در صورت وجود در عکس» برای جلوگیری از افزودن محیط خیالی. tools در این نمونه خالی است چون ابزار هدف یا ماتریس قابلیت تأییدشده‌ای ارائه نشده؛ این به معنی ناممکن بودن اجرا در ابزارهای مختلف نیست.

## تغییرات لازم سایر نودها

### RouteSwitch — اصلاح ضروری

برای هر سه مسیر، Left Value یکسان باشد:

```text
{{ $json.output.routing_category }}
```

Operator برای هر سه `is equal to`، و Right Value به صورت Fixed به ترتیب `design`، `programming` و `general` باشد. JSON.parse را از قانون general حذف کنید. در preview ابتدا تأیید کنید RouterOutputParser خروجی object در output تحویل می‌دهد؛ در صورت خروجی رشته‌ای، آن را یک بار پیش از Switch نرمال کنید و سه قرارداد متفاوت نسازید.

Fallback Output را Extra Output قرار دهید و به یک Respond to Webhook جدا با کد پاسخ 422 متصل کنید. بدنهٔ JSON خطا:

```json
{"success":false,"message":"دستهٔ مسیریابی نامعتبر است؛ پرامتی تولید نشد."}
```

این مسیر جلوی موفقیت ظاهری خروجی بدون تطابق را می‌گیرد. خطای 422 در سرور فعلی پرامتی به پیام خطای تماس با n8n تبدیل می‌شود؛ نمایش متن اختصاصی خطا نیازمند تغییر جداگانهٔ سرور است. مقدار پیش‌فرض Switch، موارد بدون تطابق را کنار می‌گذارد؛ [مستند رسمی](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.switch/).

### RouterOutputParser — اصلاح ساختار

Schema Type را Define using JSON Schema قرار دهید و [schema پیشنهادی Router](proposals/router-schema-v002.json) را وارد کنید. این schema مقدار routing_category، source_language و بازهٔ confidence را محدود می‌کند؛ محتوا و زبان واقعی همچنان نیازمند قضاوت مدل‌اند. مثال JSON به‌تنهایی enum نمی‌سازد؛ [مستند رسمی Parser](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.outputparserstructured/). متن RouterNode برای این مرحله نیازمند بازنویسی نیست.

### Code in JavaScript1 — جایگزینی ضروری

[کد جایگزین کامل](proposals/code-output-v002.js) برای JavaScript و حالت Run Once for All Items آماده شده است. این کد:

- پاسخ شیء مستقیم، wrapper رایج و یک رشتهٔ JSON را می‌خواند؛ فقط حصار بیرونی را در صورت نیاز برمی‌دارد و متن داخل JSON را تغییر نمی‌دهد.
- نوع و وجود فیلدها، گزینه‌های مجاز taxonomy، schema و تطابق متغیرهای دو زبان را کنترل می‌کند.
- فیلد legacyِ industry و فرادادهٔ Router را حذف می‌کند و نقص را با عنوان ساختگی نمی‌پوشاند.
- شمارش متغیرها را خارج از بلوک‌های کد انجام می‌دهد تا نمونه‌کد literal متغیر فرم محسوب نشود؛ خود متن کد حفظ می‌شود. کنترل شخصی‌سازی داخل بلوک کد در این نسخه پشتیبانی نمی‌شود.

این اعتبارسنج تضاد معنایی مثل تک‌رنگ در کنار پاستلی یا صحت ترجمه را اثبات نمی‌کند؛ آن‌ها وظیفهٔ Design/QA و ارزیابی انسانی‌اند. کد مشترک پس از QA قرار دارد؛ قبل از فعال‌کردن برای همهٔ ورودی‌ها، نمونهٔ programming و general نیز باید قرارداد جدید QA را طی کنند. آزمون فعلی روی حوزهٔ گرافیکی و منطق عمومی JSON انجام شده است.

### Respond to Webhook2

Respond With = JSON و Response Body = `{{ $json }}` فعلی مناسب است و تغییر لازم ندارد. آرایهٔ نمایش داده‌شده در پنل اجرای n8n لزوماً به معنی آرایه بودن بدنهٔ واقعی HTTP نیست. هنگام تست، پاسخ HTTP را جدا بررسی کنید؛ پاسخ پیشنهادی یک شیء پرامت است.

### مدل مشترک و سایر متخصص‌ها

برای این اصلاح، تغییر مدل مشترک، programming و general لازم نیست. ابتدا همین مدل با نسخهٔ جدید روی نمونه‌های ثابت سنجیده شود. اگر بعداً تنظیمات مدل Design/QA تغییر کند، اثر مدل مشترک بر Router و سایر متخصص‌ها را لحاظ کنید. اتصال به وب‌هوک refine_prompt برای این ورک‌فلوی analyze_source مناسب نیست.

## محدودیت فعلی زبان در سایت

گزینهٔ `English value|برچسب فارسی` در UI فارسی نمایش داده می‌شود، ولی بخش انگلیسی آن هم در body و هم bodyFa جایگزین می‌شود. در نمونهٔ مرجع، جملهٔ فارسی بعد از انتخاب می‌تواند شامل عبارت انگلیسیِ ضخامت یا سایه‌زنی باشد. پرامت جدید این محدودیت را پنهان نمی‌کند. خروجی تماماً فارسی پس از انتخاب، به پشتیبانی مقدار ترجمه‌شده در renderer/schema سایت نیاز دارد و در این درخواست پیاده‌سازی نشده است. اولویت گزینهٔ سازگار با اصل متن رعایت شده؛ سازوکار مقدار پیش‌فرض در تمام مسیرهای UI یکسان نیست و باید در خود فرم آزمایش شود.

## اعتبارسنجی انجام‌شده

۱۲ بررسی رفتاری محلی برای Code پاس شدند: round-trip متن، حصار بیرونی و کد درونی، body ناقص، نوع اشتباه، taxonomy نامعتبر، متغیر بدون schema، تفاوت متغیرهای ترجمه، slider نامعتبر، گزینهٔ تکراری، حالت بدون متغیر، حذف legacy و حفظ قیود نمونه با تمام ۹ ترکیب گزینه‌ها. آزمون ترکیب‌ها قیود متنی منتخب را بررسی می‌کند، نه کیفیت تصویری نتیجه را.

آزمون ابزار آرشیو، حفظ دقیق دو پیام، افزایش نسخه، یکسان بودن current/snapshot، حفظ اصل و رد وضعیت deployed بدون شاهد را تأیید کرد. اعتبارسنج رسمی Skill نیز روی نسخهٔ آماده‌شده و نصب‌شده با نتیجهٔ `Skill is valid!` موفق بود. هیچ وب‌هوک یا مدل واقعی اجرا نشده است؛ کیفیت تصویر و زمان/توکن هنوز اندازه‌گیری نشده‌اند.
